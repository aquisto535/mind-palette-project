# Quick Commit — 커밋 준비 도우미

다음 단계를 순서대로 실행하여 커밋 준비를 돕겠습니다.

## 1. 변경사항 분석

현재 git 상태를 확인하여 변경된 파일과 내용을 파악합니다.

**확인할 명령어:**
```bash
git status
git diff --staged
git diff
```
(사용자가 터미널에서 실행 후 결과 공유 시 분석)

## 2. Self-Review 체크리스트

변경사항을 바탕으로 아래 항목을 검토합니다:

- [ ] **테스트 통과**: 모든 테스트가 통과하는가?
- [ ] **변경 분리**: 구조적(Structural) 변경과 기능적(Behavioral) 변경이 분리되어 있는가?
- [ ] **불필요한 파일**: 의도하지 않은 파일 변경(공백, 디버그 코드)이 없는가?
- [ ] **시크릿 없음**: API 키, 비밀번호 등이 하드코딩되어 있지 않은가?
- [ ] **.gitignore**: 추가해야 할 파일이 없는가?

## 3. 커밋 메시지 생성

`docs/guides/git-workflow-guide.md`의 Conventional Commits 규칙에 따라 커밋 메시지를 제안합니다:

```
<타입>(<범위>): <제목>

<본문> (변경 이유와 내용, 선택사항)
```

**타입 선택 기준:**
| 타입 | 상황 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `test` | 테스트 추가/수정 |
| `refactor` | 리팩터링 (동작 변경 없음) |
| `docs` | 문서 변경 |
| `chore` | 빌드/설정 변경 |

## 4. 실행 명령어 제공

검토 완료 후 터미널에서 직접 실행할 명령어를 제공합니다:

```bash
git add <파일들>
git commit -m "<커밋 메시지>"
```

> ⚠️ **주의**: main 브랜치가 아닌 feature 브랜치에서 커밋하세요.
> 현재 브랜치 확인: `git branch`
