# Mind Palette 프로젝트 - 데이터 관점에서의 이해

## 1. 프로젝트가 다루는 데이터 분해

Mind Palette는 **아동의 그림을 AI로 분석하여 지능·심리 특성을 측정하는 시스템**입니다. 데이터 관점에서 나누면 크게 4가지 데이터가 흐릅니다:

| 단계 | 입력 데이터 | 처리 | 출력 데이터 |
|------|------------|------|------------|
| **수집** | 아동 정보 (이름, 성별, 생년월일) + 그림 이미지 | 사용자 입력 | `ChildInfo` + 이미지 파일 |
| **전처리** | 원본 이미지 (JPEG/PNG) | 리사이즈, 노이즈 제거, 이진화 등 | 정제된 이미지 |
| **분석** | 정제된 이미지 | AI 모델 추론 (예정) | 점수, 백분위, 세부 지표 |
| **표시** | 분석 결과 JSON | 시각화 | 트리 시각화 + 백분위 그래프 |

---

## 2. 핵심 데이터 구조

```
[사용자가 입력하는 데이터]
ChildInfo {
  name: string          // 아동 이름
  gender: string        // 성별
  birthDate: string     // 생년월일
}

[시스템이 생성하는 데이터]
AnalysisResult {
  score: number         // 종합 점수 (70~95)
  percentile: number    // 백분위 (60~99)
  interpretation: string // AI 해석 텍스트
  date: string          // 분석 날짜
  details: {
    creativity: number    // 창의성 (0~100)
    expression: number    // 표현력 (0~100)
    observational: number // 관찰력 (0~100)
  }
}
```

핵심은 **비정형 데이터(이미지)**를 → **정형 데이터(점수, 백분위)**로 변환하는 것입니다.

---

## 3. 아키텍처를 데이터 흐름으로 이해하기

```
[사용자 브라우저]          [API Gateway]         [C++ 서버]          [AI 서버(예정)]
     │                        │                     │                    │
     │── 이미지 + 아동정보 ──→│                     │                    │
     │                        │── 이미지 경로 ──────→│                    │
     │                        │                     │── 전처리된 이미지 ─→│
     │                        │                     │                    │
     │                        │←── 전처리 경로 ─────│                    │
     │                        │←─────────────── 분석 결과 JSON ─────────│
     │←── AnalysisResult ────│                     │                    │
```

각 서버가 존재하는 이유를 데이터 특성으로 설명하면:

| 서버 | 왜 이 기술? | 데이터 특성 |
|------|------------|------------|
| **React 프론트엔드** | 사용자 인터랙션 + 시각화 | 폼 입력, 드래그앤드롭, 그래프 렌더링 |
| **Node.js API Gateway** | 요청 라우팅 + 파일 관리 | JSON 파싱, 멀티파트 업로드, 비동기 I/O에 적합 |
| **C++ 전처리 서버** | 픽셀 단위 연산 성능 | 이미지 = 거대한 숫자 배열 → CPU 집약적 → C++이 최적 |
| **Python AI 서버** (예정) | 딥러닝 생태계 | PyTorch/EfficientNet 등 AI 프레임워크가 Python 기반 |

---

## 4. 알고리즘과 데이터의 연결

**C++ 전처리 파이프라인**이 가장 알고리즘이 집중된 부분입니다:

```
원본 이미지 (H×W×3 배열)
    │
    ├─ Letterbox Resize → 512×512 (종횡비 유지, 패딩)
    │   → 왜? AI 모델은 고정 크기 입력이 필요
    │
    ├─ Gaussian Blur (5×5) + Median Blur (3)
    │   → 왜? 노이즈 제거. 가우시안=일반 노이즈, 미디안=점 노이즈에 효과적
    │
    ├─ Grayscale 변환 (3채널 → 1채널)
    │   → 왜? 그림의 '선'을 분석하므로 색상 정보 불필요, 연산량 1/3로 감소
    │
    └─ Adaptive Threshold → 이진화 → BGR 3채널 변환
        → 왜? AI 모델 입력 형식에 맞춤
```

**요약하면:** 아이의 그림에서 **"선의 형태와 구조"**라는 본질적 데이터만 추출하는 과정입니다.

---

## 5. 현재 상태와 남은 과제

```
✅ Phase 1: 프론트엔드 (데이터 수집 + 시각화)
✅ Phase 2: API Gateway (데이터 라우팅 + 저장)
✅ Phase 3: C++ 전처리 (이미지 → 정제된 이미지)
🚧 Phase 4: Python AI 서버 (정제된 이미지 → 분석 결과)  ← 다음 단계
🚧 Phase 5: 통합 배포 (Docker + AWS)
```

현재 API Gateway는 **목(mock) 데이터**로 분석 결과를 생성하고 있습니다. Phase 4에서 EfficientNet-B2 모델이 연결되면, 실제 AI 추론으로 대체됩니다.

---

## 6. 비유로 정리

Mind Palette를 **병원 검사**에 비유하면:

- **프론트엔드** = 접수 창구 (환자 정보 수집, 결과지 전달)
- **API Gateway** = 간호사 (검체를 올바른 검사실로 전달)
- **C++ 전처리** = 검체 준비실 (혈액에서 불순물 제거, 분석 가능한 상태로 만듦)
- **AI 서버** = 의사 (준비된 검체를 보고 진단 내림)

각 단계가 분리되어 있어서, 한 부분을 바꿔도 다른 부분에 영향을 주지 않는 **마이크로서비스 구조**입니다.
